## 2. 開発ロードマップ

### 2.1 優先順位一覧

| 優先 | 項目 | 依存関係 |
| --- | --- | --- |
| 1 | レール座標によるオンレール判定 | なし（2の前提） |
| 2 | プレイヤーの自立（ジャンプ＋WASD移動） | 1が必要 |
| 3 | 的の配置の直感化 | なし（独立して着手可能） |
| 4 | 敵を作る | 3があると効率的 |
| 5 | ボス戦を作る | 4が必要 |
| 6 | JSONホットリロード機能 | なし（優先度低・後回し） |

### 2.2 各項目の詳細

#### 1. レール座標によるオンレール判定
- プレイヤーのワールド座標からレール上の最近傍点・距離を算出し、一定範囲内なら「レールに乗っている」と判定するロジックを実装する。
- 現状 GameScene.cpp に残っている分岐移動の暫定処理（LEFT/RIGHT どちらでも乗り移れる状態）の置き換え・土台にもなる。
- 2（プレイヤーの自立）の前提となる機能のため先に着手する。

#### 2. プレイヤーの自立（ジャンプ＋WASD移動）
- 現状はレールに乗った状態で自動的に進むのみ。ジャンプ操作と WASD による自由移動を追加し、レールから飛び降りて別のレールに乗り移れるようにする。
- オンレール／オフレールの状態管理、着地時の再判定に 1 の機能を利用する。

#### 3. 的の配置の直感化
- 的（ターゲット）をより直感的に配置できるツール・仕組みを検討する（ImGui 等での配置 UI を想定）。
- 他の項目と依存関係が薄く、独立して着手可能。

#### 4. 敵を作る
- 敵キャラクターの新規実装（移動・当たり判定・描画）。
- 配置には 3 の配置ツールがあると効率的なため、3 の後に着手するのが望ましい。

#### 5. ボス戦を作る
- 4 で作る敵の仕組みを土台にしたボス戦（専用の攻撃パターン・HP 管理・演出）。
- 4 に依存し、実装規模も最大のため最後に着手する。

#### 6. JSONホットリロード機能（優先度低・後回し）
- 実行中に ImGui で変更した値を、そのままファイルへ保存・反映できるようにする。

### 2.3 3日で着手する場合のおすすめ

**「1. レール座標によるオンレール判定」が最適。**
スコープが明確で、既存の暫定実装（GameScene.cpp の LEFT/RIGHT 暫定処理）の改善にもなり、2 以降の前提になる基盤機能のため。

## 3. 現状の課題（随時更新）

> 実装済みの機能一覧はコードを見れば分かるため省略し、暫定対応・不足点のみ記載する。

### 3.1 暫定対応のまま残っている箇所

- **レール間分岐移動**：分岐先が左右どちらにあるかは自動判定しているが、現状は動作確認のため LEFT/RIGHT どちらのキーでも乗り移れる暫定状態（GameScene.cpp）。左右限定に絞る場合は要調整。

### 3.2 コードレビューで見つかった不足点（2026-08-26時点、要優先度調整）

**ゲームシステム**
- ゲームオーバー条件が存在しない。被弾・失敗の概念自体がなく、SceneFactory にも GAME_OVER 相当のシーンがない（クリアのみの一本道）。
- プレイヤー側の当たり判定（コライダー）が存在しない。敵・障害物と衝突する仕組みがまだない。「敵を作る」の実装前に用意する必要がある。
- スコア・残機・タイマーなどのゲーム状態が一切ない（撃破数のカウントすら未実装）。
- ポーズ機能がない。

**UI・演出**
- 撃破数・残り的数・スコアなどの HUD 表示がない（画面中央レティクル以外の表示がない）。
- クリア画面の "STAGE CLEAR!" 表示や GameScene.cpp の分岐デバッグ表示が ImGui ウィンドウで代用されている。本番用 UI としてはスプライト／テキスト描画に置き換える想定。

**サウンド**
- SoundManager は存在するが、GameScene.cpp 内で一度も呼ばれていない。発射音・被弾音・BGM が未実装。

**実装品質・パフォーマンス**
- 弾（Bullet）を発射のたびに `make_unique<Obj3D>` して Initialize している（GameScene.cpp 内の発射処理）。オブジェクトプーリングされておらず、連射時に生成・破棄が毎フレーム発生しうる。「無駄な処理を繰り返す非効率なコーディング禁止」の規約に抵触しやすい箇所。
- 的の配置が GameScene.cpp 内にハードコードされた定数ループ（kTargetCount 等）で、JSON 化・エディタ化されていない（ロードマップ 3「的の配置の直感化」で対応予定）。

## 4. 開発ルール

### 4.1 コーディング規約

- **命名規則・インデント**：一般的な C++ の規約に準拠すること。
- **コメントアウト**：処理の意図や内容をなるべく細かく具体的に記述すること。

### 4.2 実装時の禁止事項

- マジックナンバーの使用を禁止する。必ず定数（constexpr 等）を使用すること。
- 無駄な処理を何度も繰り返すような、非効率なコーディングをしないこと。

### 4.3 AIへの指示（厳守事項）

- 回答は短く簡潔にすること。
- 聞かれたこと以外の余計なコードを追加しないこと。
- コードの順番を勝手に変更しないこと。
- 変更箇所にはわかりやすい目印をつけること（ただし特殊な記号は使用しない）。
- コメントアウトに不自然な記号を使用しないこと。
- 提示されたコードを省略して返すのは禁止。
- 「整理して」と指示された場合は、処理内容は一切変更せず、不要なコメントの削除・わかりやすいコメントの追加・インデントの改善のみ行うこと（見やすさのための順番変更は許可する）。
