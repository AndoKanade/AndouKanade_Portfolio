## 3. 現状の課題（随時更新）

> 実装済みの機能一覧はコードを見れば分かるため省略し、暫定対応・不足点のみ記載する。

### 3.1 暫定対応のまま残っている箇所

- **タイトルの仮素材**：カウントダウンは ImGui で表示している。Release 構成では ImGui が無いためカウントダウンが表示されない。本番の素材ができたら差し替える。
- **タイトルの開始位置**：今はレールの始点から始まる。台の上を自由に動いてからレールに乗る流れは後で作る。

### 3.2 コードレビューで見つかった不足点（2026-09-19時点、要優先度調整）

**ゲームシステム**
- スコア・残機・タイマーなどのゲーム状態がない（撃破数のカウントが未実装）。プレイヤーの体力（playerHp_）のみ存在する。
- ポーズ機能がない。
- 当たり判定はモデルの頂点から求めた境界球（Model::BoundingSphere）同士で行っている。プレイヤーは敵弾との判定（境界球と無敵時間）だけで、敵本体や障害物との接触判定は未実装。
- 弾とステージの壁・床の判定や、地面を塗る演出を入れる場合は、弾の移動線分とポリゴンの判定が必要になる（今後対応予定）。

**UI・演出**
- HUD 表示がない（画面中央レティクル以外の表示がない）。プレイヤーの体力も敵の体力も ImGui のデバッグウィンドウにしか出ていない。
- クリア画面の "STAGE CLEAR!"、ゲームオーバー画面の "GAME OVER" が ImGui ウィンドウで代用されている。本番用 UI としてはスプライト／テキスト描画に置き換える想定。

**サウンド**
- SoundManager は存在するが、GameScene.cpp 内で一度も呼ばれていない。発射音・被弾音・BGM が未実装。

**実装品質・パフォーマンス**
- プレイヤーの弾（Bullet）を発射のたびに `make_unique<Obj3D>` して Initialize している（GameScene.cpp 内の発射処理）。敵弾は Enemy 側で使い回しているため、プレイヤーの弾も同様にプーリングしたい。

## 4. 開発ルール

### 4.1 コーディング規約

- **命名規則・インデント**：一般的な C++ の規約に準拠すること。
- **コメントアウト**：処理の意図や内容をなるべく細かく具体的に記述すること。

### 4.2 実装時の禁止事項

- マジックナンバーの使用を禁止する。必ず定数（constexpr 等）を使用すること。
- 無駄な処理を何度も繰り返すような、非効率なコーディングをしないこと。

### 4.3 AIへの指示（厳守事項）

- 回答は短く簡潔にすること。
- 聞かれたこと以外の余計なコードを追加しないこと。
- コードの順番を勝手に変更しないこと。
- 変更箇所を示す目印コメント（「ここから追加」「ここまで追加」など）は書かないこと。処理の意図を説明するコメントのみ記述する。
- コメントアウトに不自然な記号を使用しないこと。
- 提示されたコードを省略して返すのは禁止。
- 「整理して」と指示された場合は、処理内容は一切変更せず、不要なコメントの削除・わかりやすいコメントの追加・インデントの改善のみ行うこと（見やすさのための順番変更は許可する）。
