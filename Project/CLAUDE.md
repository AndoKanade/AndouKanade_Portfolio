## 2. 開発ロードマップ

### 2.1 優先順位一覧

| 優先 | 項目 | 依存関係 | 状況 |
| --- | --- | --- | --- |
| 1 | レール座標によるオンレール判定 | なし（2の前提） | 完了 |
| 2 | プレイヤーの自立（ジャンプ＋WASD移動） | 1が必要 | 完了 |
| 3 | 的の配置の直感化 | なし（独立して着手可能） | 完了 |
| 4 | 敵を作る | 3があると効率的 | 完了 |
| 5 | ボス戦を作る | 4が必要 | 未着手（次の着手対象） |
| 6 | JSONホットリロード機能 | なし（優先度低・後回し） | 一部対応 |

### 2.2 各項目の詳細

#### 1. レール座標によるオンレール判定（完了）
- プレイヤーのワールド座標からレール上の最近傍点・距離を算出し、一定範囲内なら「レールに乗っている」と判定する。
- RailEditor::FindNearestRail() と GameScene の isOnRail_ / kOnRailDistanceThreshold_ で実装済み。

#### 2. プレイヤーの自立（ジャンプ＋WASD移動）（完了）
- LSHIFT でレールを離れ、オフレール中は WASD で水平移動、重力で落下する。
- 落下中に 1 のオンレール判定を行い、条件を満たしたレールへ乗り移る。

#### 3. 的の配置の直感化（完了）
- TargetEditor（Game/Editor/TargetEditor.cpp）で実装。Sceneビュー上のマウスドラッグで的を移動でき、配置内容は resource/target/target.json に保存・読み込みできる。

#### 4. 敵を作る（完了）
- Enemy（Game/objects/Enemy.cpp）で実装。固定パターンの往復移動、プレイヤー検知、敵弾の発射（弾は初期化時にまとめて生成して使い回す）、体力による撃破判定を持つ。
- 配置は EnemyEditor（Game/Editor/EnemyEditor.cpp）で行う。座標・往復方向・最大HP を敵ごとに編集でき、resource/enemy/enemy.json に保存・読み込みできる。

#### 5. ボス戦を作る（未着手・次の着手対象）
- 4 で作った敵の仕組みを土台にしたボス戦（専用の攻撃パターン・HP 管理・演出）。
- Enemy の体力・弾の使い回しの仕組みはそのまま流用できる。

#### 6. JSONホットリロード機能（一部対応・優先度低）
- GlobalVariables による調整項目（resource/GlobalVariables/GameScene.json）は、実行中の ImGui 編集と外部ファイル書き換えの反映に対応済み。
- レール・的・敵の配置データは各エディターの Save / Load ボタンによる手動操作のため、自動反映は未対応。

### 2.3 次に着手する場合のおすすめ

**「5. ボス戦を作る」または 3.2 の HUD・サウンド対応。**
ロードマップ 1〜4 は完了しており、ボス戦は既存の Enemy の仕組みをそのまま拡張できる。ただし現状は体力・撃破状況が ImGui のデバッグ表示にしか出ていないため、先に HUD を整えるとボス戦の手応えが分かりやすくなる。

## 3. 現状の課題（随時更新）

> 実装済みの機能一覧はコードを見れば分かるため省略し、暫定対応・不足点のみ記載する。

### 3.1 暫定対応のまま残っている箇所

- **レール間分岐移動**：分岐先が左右どちらにあるかは自動判定しているが、現状は動作確認のため LEFT/RIGHT どちらのキーでも乗り移れる暫定状態（GameScene.cpp）。左右限定に絞る場合は要調整。

### 3.2 コードレビューで見つかった不足点（2026-09-19時点、要優先度調整）

**ゲームシステム**
- スコア・残機・タイマーなどのゲーム状態がない（撃破数のカウントが未実装）。プレイヤーの体力（playerHp_）のみ存在する。
- ポーズ機能がない。
- プレイヤーの当たり判定は敵弾との距離判定（kPlayerHitRadius_ と無敵時間）だけで、汎用のコライダーが無い。敵本体や障害物との接触判定は未実装。

**UI・演出**
- HUD 表示がない（画面中央レティクル以外の表示がない）。プレイヤーの体力も敵の体力も ImGui のデバッグウィンドウにしか出ていない。
- クリア画面の "STAGE CLEAR!"、ゲームオーバー画面の "GAME OVER"、GameScene.cpp の分岐デバッグ表示が ImGui ウィンドウで代用されている。本番用 UI としてはスプライト／テキスト描画に置き換える想定。

**サウンド**
- SoundManager は存在するが、GameScene.cpp 内で一度も呼ばれていない。発射音・被弾音・BGM が未実装。

**実装品質・パフォーマンス**
- プレイヤーの弾（Bullet）を発射のたびに `make_unique<Obj3D>` して Initialize している（GameScene.cpp 内の発射処理）。敵弾は Enemy 側で使い回しているため、プレイヤーの弾も同様にプーリングしたい。

### 3.3 対応済みになった項目（2026-09-19）

- **ゲームオーバー条件**：プレイヤーの体力が0になると GAMEOVER シーンへ遷移するようになった（GameOverScene.cpp / SceneFactory.cpp / GameScene.cpp）。
- **的の配置のエディタ化**：GameScene.cpp のハードコードから TargetEditor + resource/target/target.json へ移行済み（保存データが無い初回起動時のみ自動配置する）。
- **敵の配置のエディタ化と敵の体力**：EnemyEditor + resource/enemy/enemy.json で複数体を配置でき、敵ごとに最大HPを設定できる。プレイヤーの弾1発につき kBulletDamageToEnemy_ ぶん体力が減り、0になったときだけ撃破される。

## 4. 開発ルール

### 4.1 コーディング規約

- **命名規則・インデント**：一般的な C++ の規約に準拠すること。
- **コメントアウト**：処理の意図や内容をなるべく細かく具体的に記述すること。

### 4.2 実装時の禁止事項

- マジックナンバーの使用を禁止する。必ず定数（constexpr 等）を使用すること。
- 無駄な処理を何度も繰り返すような、非効率なコーディングをしないこと。

### 4.3 AIへの指示（厳守事項）

- 回答は短く簡潔にすること。
- 聞かれたこと以外の余計なコードを追加しないこと。
- コードの順番を勝手に変更しないこと。
- 変更箇所を示す目印コメント（「ここから追加」「ここまで追加」など）は書かないこと。処理の意図を説明するコメントのみ記述する。
- コメントアウトに不自然な記号を使用しないこと。
- 提示されたコードを省略して返すのは禁止。
- 「整理して」と指示された場合は、処理内容は一切変更せず、不要なコメントの削除・わかりやすいコメントの追加・インデントの改善のみ行うこと（見やすさのための順番変更は許可する）。
